OmaAudit
Install Commands Accuracy GitHub

See what an Omarchy tool will do to your machine before you install it.

OmaAudit is a small command-line tool. It reads a tool's install scripts, systemd units, Hyprland config and plugin files, and shows you what they do: what gets downloaded and run, where root is requested, what keeps running after you log in. It reports evidence, not verdicts. The decision stays with you.

What a report looks like

Real output from a real Omarchy plugin, shortened. Every finding names the file, the line and the code itself, so you can check it.

$ omaaudit scan ./omaga-sync

Summary  REVIEW RECOMMENDED  4 medium, 3 low
  capabilities: build-from-source, network-download, omarchy-plugin, persistence

Findings
MEDIUM   OA-SH-007 A service, timer or autostart entry is installed
         install.sh:48  writes into an autostart or unit directory: $HOME/.config/systemd/user/
         │ install -m 644 "$SRC_DIR/omaga-sync-engine.service" "$UNIT_DST/"
MEDIUM   OA-SH-003 Code is obtained from a mutable remote reference and built or installed
         README.md:78  git clone of a mutable reference (this is what users are told to run)
         │ git clone https://github.com/bismawy/omaga-sync.git
LOW      OA-SH-007 A service, timer or autostart entry is installed
         install.sh:67  systemctl --user enables a unit
         │ systemctl --user enable --now omaga-sync-engine.service

Coverage
  17 of 41 files inspected (140 KiB); skipped 24
  unknown: 2 Python/JavaScript file(s) are only scanned for secrets
  unknown: 5 QML file(s): only process/file/network surfaces are analysed

Findings are evidence of risk patterns, not proof of malice, and the
absence of findings is not proof of safety.

How to read it

Severity describes the action

"High-risk indicators" means this is what the files show, not that the author is malicious. Plenty of honest tools need root or a background service. You should know before you run them.

Clean is not a certificate

No findings means these rules found nothing in the files they could read. Each report lists what it could not inspect.

Nothing is executed

OmaAudit only reads. It never runs the scripts, hooks, builds or binaries of the tool it is looking at.

Install

OmaAudit needs Node.js 24 or newer. Omarchy ships Node through mise. It is not on npm yet, so install it from source:

git clone https://github.com/hasky00/OmaAudit.git
cd OmaAudit
npm ci --ignore-scripts
npm run build
npm link

Then check your setup:

omaaudit doctor

Optional, for more findings: sudo pacman -S shellcheck osv-scanner. To remove OmaAudit: npm unlink -g omaaudit and rm -rf ~/.cache/omaaudit.

Commands

CommandWhat it does
omaaudit check owner/repoFetches the repository at an exact commit and inspects install scripts, privileges, downloads, persistence, secrets and dependencies.
omaaudit scan .Audits a local folder, offline, without uploading anything. Works on a plugin you already have, or one you are writing.
omaaudit find "query"Searches the Omarchy plugin marketplace catalog and GitHub, and shows why each result matched.
omaaudit compare a bPuts two tools side by side: capabilities, dependencies, maintenance and findings.
omaaudit doctorRead-only check of your Node version, optional scanners and GitHub access.

Every command takes --json. Full reference: docs/cli.md.

For plugin authors

Run omaaudit scan . on your own plugin before you publish. It shows you what a careful user will see, and it is quicker to hear "your installer enables a service at login" from a tool than from a bug report.

If a finding about your project is wrong, please open an issue. False alarms are treated as bugs.

How accurate is it

This is an early preview, and it has been measured rather than promised. The rules were run on 20 marketplace plugins they had never seen, and every finding was labeled by an AI reviewer (Claude) working separately from the session that wrote the rules. One reviewer, one pass, a small sample.

  • Every finding checked pointed at the right file and line.
  • About 90% of all findings were correct, most of them informational notes such as "this plugin spawns processes".
  • The louder warnings were weaker: 9 of 21 findings at medium or above were correct for code a user runs.
  • All five critical findings in that run were false alarms with one shared cause. That bug is being fixed.
  • It also missed behaviours that had no rule yet, such as a plugin adding hooks to AI coding agent settings.

The full data, labels and method are in the repository under docs/corpus. Python and JavaScript logic is not analysed yet, only scanned for secrets.
